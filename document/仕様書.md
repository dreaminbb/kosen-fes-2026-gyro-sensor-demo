## マイコン処理
---
### センサー処理
センサーを読みデータを取得する。
対象基板はSeeed Studio XIAO MG24 (Sense)。現ファームウェアではLSM6DS3の実測加速度（g）と角速度（度/秒）を100 Hzで送る。

```c
constexpr unsigned long SENSOR_SEND_INTERVAL_MS = 10;  // 10 ms = 100 Hz
```


**参考文献**
- [seedstudio.com 加速度計リファレンス](https://wiki.seeedstudio.com/ja/xiao_mg24_sense_built_in_sensor/)


### PC送信処理

加速度センサーの値を PC の Godot へ送り、操作に使う。

- 無線通信はBLE 5.3のGATTを使う。MG24がKosenBallとしてアドバタイズし、ESP32-C6が接続する。GodotはC6のUSBシリアルを使う。
- MG24からGodotへはNotificationでテレメトリーを送り、GodotからMG24へは同じ特性へのWrite Without Responseでコマンドを送る。
- GATTのUUID、行形式、コマンド一覧はdocument/通信方式.mdを参照する。

## コントローラー中間処理
---
### PCとの初期接続
受信するxiao seedとPCとはシリアルで有線接続をする。
実行する環境によって、接続されるファイルは異なるが、Mac/Linuxは共通で`/dev/`直下のファイルへとアタッチされる。

### 接続不良時の再接続、処理
LinuxではUSB機器を接続しても、利用者にデバイスを開く権限がなければ、Arduino CLIとGodotは利用できない。本機ではシリアルポートの所有グループを`uucp`としている。

#### ポートと必要な権限

| 機器 | 用途 | 現れるデバイス | 必要な権限 |
| --- | --- | --- | --- |
| XIAO ESP32-C6 | 書き込み、GodotとのUSBシリアル通信 | `/dev/ttyACM*` | 利用者が`uucp`グループで読み書きできること |
| XIAO MG24 (Sense) | シリアルログ | `/dev/ttyACM*` | 利用者が`uucp`グループで読み書きできること |
| XIAO MG24 (Sense) | OpenOCDによる書き込み | `/dev/bus/usb/BBB/DDD`（CMSIS-DAP、USB ID `2886:0062`） | `uucp`グループが読み書きできること |

`ttyACM0`と`ttyACM1`の番号は接続順や再接続で入れ替わる。番号を固定の基板名として扱わず、`arduino-cli board list`、`lsusb`、またはGodotのポート選択で接続先を確認する。MG24への書き込みはシリアルポートだけでは足りず、CMSIS-DAPのUSBデバイスへの権限も必要である。

#### 恒久的な対処

次を一度だけ実行する。`shin`は実際のLinux利用者名に置き換える。

```sh
sudo usermod -aG uucp shin
printf '%s\n' 'SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{idVendor}=="2886", ATTR{idProduct}=="0062", MODE="0660", GROUP="uucp"' | sudo tee /etc/udev/rules.d/70-xiao-mg24.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

グループ追加は、新しく開始したログインセッションにだけ反映される。実行後は一度ログアウトしてログインし直す。再起動は必要ないが、ログアウトできない場合の代替になる。ルールを追加した後は、MG24を一度抜き差しすると新しい権限で作成される。

設定後の確認:

```sh
id -nG
ls -l /dev/ttyACM*
lsusb -d 2886:0062
arduino-cli board list
```

`id -nG`の結果に`uucp`があり、`/dev/ttyACM*`のグループが`uucp`であれば、C6とMG24のシリアルを通常の利用者で開ける。MG24の書き込み前には、`lsusb -d 2886:0062`でCMSIS-DAPが見えていることも確認する。

#### 一時的な対処

ログアウト前やudevルールをまだ設定できない場合は、現在接続中のデバイスにだけACLを付与できる。MG24のUSBデバイス番号は抜き差しのたびに変わるため、必ずその場で`lsusb`から取得する。

```sh
mg24_usb=$(lsusb -d 2886:0062 | awk '{gsub(":", "", $4); print "/dev/bus/usb/" $2 "/" $4}')
sudo setfacl -m u:shin:rw /dev/ttyACM0 /dev/ttyACM1 "$mg24_usb"
getfacl /dev/ttyACM0 /dev/ttyACM1 "$mg24_usb"
```

この設定はデバイスを抜き差しすると失われる。`$mg24_usb`を次行に単独で入力すると、そのデバイスをコマンドとして実行しようとして`permission denied`になるため、必ず上の`setfacl`コマンドの引数として使う。

#### 実行時の注意と切り分け

- `arduino-cli monitor`、`arduino-cli upload`、Godotは`sudo`を付けず、同じ通常利用者で実行する。`sudo arduino-cli monitor`はroot側のArduino設定を参照するため、通常利用者で動くポート監視が`No monitor available for the port protocol serial`で失敗することがある。
- `Permission denied`またはOpenOCDの`unable to open CMSIS-DAP device 0x2886:0x62`は、MG24の`/dev/bus/usb/BBB/DDD`権限を確認する。`/dev/ttyACM*`だけにACLを付けてもMG24の書き込みは解決しない。
- `arduino-cli board list`に何も表示されず、`lsusb`にも機器がない場合は権限の問題ではない。USBケーブル、ハブ、接続状態、または基板の電源を確認する。
- ポートが`Permission denied`ではなく`Device or resource busy`になる場合は、Godot、`arduino-cli monitor`、シリアルターミナルのいずれかが同じポートを開いている。先に開いているプログラムを終了してから使う。

## ゲーム処理
---
### データの受診

`高専祭玉転がし/scripts/ble_monitor.gd` がC6の `RX,DATA,...` を解析し、加速度XYZから求めたPitch/Rollで台を傾ける。初回の受信姿勢を水平の基準とし、「水平を合わせる」で現在のセンサー姿勢を基準に取り直せる。Yawは数値表示に使い、台の傾きには反映しない。

### コースとルール

`scripts/ball_platform.gd` が長さ32 m・幅8 mのコースを生成する。START（Z=14 m）からGOAL（Z=-14 m）へ進む。

1. 左右の開口を交互に通るオレンジの壁。
2. 紫の柱を避け、右寄りの幅1.8 m・長さ3 mの橋を渡る。橋の左右には床も見えない衝突形状もなく、球は落下する。
3. 最後の柱を避けて緑のGOALリングへ入る。

黄色い線が2か所のチェックポイント。順番に通過すると緑になり、落下後の再開地点になる。2か所を通過してGOALへ入るとクリアし、球を停止して時間・落下回数を表示する。「もう一度」で最初から再挑戦できる。

### パラメータ

Godotの1単位を1 mとして扱う。

- 床の厚さ: 0.2 m。球の半径: 0.22 m、質量: 0.5 kg。
- Pitch/Roll: 各軸±18°まで。係数48/秒の指数補間で追従（時定数約21 ms）。
- 摩擦係数: 台・球とも0.65。球の反発係数: 0.1。
- 物理エンジン: Jolt Physics、120 Hz。物理補間を有効にする。
- 操作開始からの経過時間、現在の区間、チェックポイント、落下回数、速度（m/秒）を表示。
- カメラは補間済みの球位置を追い、進行方向の少し先を映す。「コース全体」で俯瞰表示へ切り替えられる。
- Godotは全画面で起動する。ゲーム画面を全面に表示し、レース状況・操作案内・センサー値を重ねたパネルで表示する。シリアルポート・BLEコマンド・受信ログは「接続設定」パネルにまとめる。UIと3Dコースの色はCatppuccin Mochaを使う。

### 物理演算

台・壁・柱・橋を1つの `AnimatableBody3D` の衝突形状として傾ける。球は独立した `RigidBody3D` とし、重力・摩擦・衝突によって位置、速度、回転を計算する。長い台を中心から回すと端の球が跳ね上げられるため、球の足元を固定して台を回す。通常の移動では球の位置・速度を書き換えない。

球がコースの床より3 m下に落ちる、またはコースのX/Z境界から3 m外へ出ると、最後のチェックポイント（未通過ならSTART）の1.8 m上から再出現する。判定と再開地点は傾いた台の座標系で計算する。`scripts/rolling_ball.gd` の `_integrate_forces()` で位置・姿勢・直線速度・角速度をリセットし、重力で台へ落とす。

「もう一度」は時間・チェックポイント・落下回数をリセットする。MG24からの `ACK,RESET` では水平基準とゲームを両方リセットする。BLE切断や250 msのデータ停止時は方向キー操作へ切り替わり、キーを押していなければ台が水平に戻る。ポート入力中は方向キーで台を動かさない。

### 更新周期

MG24は10 msごとにセンサーを読み、100 Hzで送信する。送信時刻へ10 msを加算して周期を保ち、処理の遅れを毎回積み上げない。C6は標準出力の追加バッファを無効にして完成したRX行をUSBへ渡す。

Godotは台の物理処理より前に120 Hzの物理tickでパイプを読み、受信した姿勢を直ちに目標角度へ反映する。まとめて届いた行はすべて解析し、最新の姿勢で台を更新する。センサー値・受信カウンター・ゲームHUDの文字表示のみ10 Hzとし、入力処理や物理演算に待ち時間を入れない。画面の「最終受信」はPCが最新行を受け取ってからの時間で、センサーから画面までの総遅延ではない。

### 動作確認

Godot 4.7.2 / Jolt Physics / Metalで、STARTへの着地、壁との実際の衝突、橋の左右からの落下、橋上への着地、2か所のチェックポイント、傾いた台への再出現、GOAL・リスタートを確認した。10°の入力に約58 ms以内で90%以上追従することと、DATA入力・RESETの反映も確認した。実機を手で傾けた際の各軸の方向と体感遅延の確認は未実施。

### godbotの操作

Godotを再起動し、C6のシリアルに接続する。コントローラーを操作の基準姿勢に置き、「水平を合わせる」を押してから傾ける。壁・柱を避けて橋を渡り、奥のGOALへ進む。落下時は最後のチェックポイントの上から戻る。「もう一度」で最初から再挑戦、「コース全体」でルートを確認できる。BLE未接続時は↑↓で前後、←→で左右へ球を転がせる。
